# Windows 任务栏模式

Windows 开发版在「设置 → 外观显示 → Windows 任务栏」中提供入口。macOS 不增加此入口，仍沿用原面板、悬浮球和菜单栏表现。

任务栏采用「直切三栏」布局：左侧为来源和账户，右侧为三栏数值及刷新。单击来源直接轮换；箭头列出站点下的各个账户；单击数值或右键打开详情，可返回完整面板、打开设置或退出任务栏模式。

官方沿用已保存的 `dataBars` 配置及套餐默认值；估算带 `≈`，详情注明不是余额或账单。三方订阅显示今日消耗、周期剩余金额和窗口剩余；钱包显示今日消耗、余额和按量计费，不使用内部兼容百分比。缺失值显示 `--`。同一来源读取失败保留缓存，切换来源后旧请求结果不再写入当前界面。

抓手支持拖动至桌面自由悬浮；靠近任务栏空白时显示占位，松手吸附。双击抓手或聚焦后按 Enter 可重新吸附。原生实现关联任务栏 owner，并结合 UI Automation 控件边界、托盘区域和其他附属窗口计算空白，不向 Explorer 注入代码。空间不足时退回悬浮，待空间恢复后重试。当前横向布局不吸附竖向任务栏。

维护扫描必须排除整个组件窗口树：WebView2 的按钮可能属于渲染子进程，仅排除主进程 PID 会把组件自己当成障碍，造成位置来回切换。位置未变时也不重复设置 owner、层级或显示状态。

任务栏本身处于 topmost 层。组件与吸附预览需要在关联 owner 后明确进入同一层，并排在任务栏上方；仅使用 `HWND_TOP` 会出现图像可见但鼠标命中 `MSTaskListWClass` 的情况，表现为点击与拖动均无响应。停靠状态仍保留全屏覆盖检测，进入全屏应用时隐藏组件。

任务栏窗口只接收展示字段和来源标识，不接收 API Key 或站点 URL；仍由主窗口负责原有接口请求和定时刷新。启用状态使用新增 `taskbarEnabled` 设置保存，旧配置默认为关闭。

自动检查覆盖三种格式、缺失字段、估算语义、配置保留、来源结果隔离、启用回滚、macOS 入口隔离及空白区计算。界面检查使用独立 Edge 和模拟 IPC；Windows 原生吸附、拖动和位置稳定性需另用开发版实测，不能以浏览器模拟替代。多屏缩放、自动隐藏任务栏、Explorer 重启及 macOS 真机仍需对应环境回归。
